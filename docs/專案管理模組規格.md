# 工作流程管理系統　專案管理模組　規格書

> 版本：v1.0　建立日期：2026-06-06　文件狀態：待主管確認補充

> 本文件為「工作流程管理系統」之專案管理模組詳細規格，搭配總體需求規格（需求規格.md）第 10 章使用。

## 1. 模組目的與定位

專案管理模組提供「專案」作為跨流程的管理單位。一個專案（通常對應一個客戶案）可串接多個流程（銷售、系統導入、環境建置、客製化等），讓主管與承辦能在單一視角掌握該案整體進度、各流程銜接狀態、時程風險，並支援內部會議簡報與專案層級的時程管理。

模組與既有流程之關係：流程（案件）為實際作業單位，專案為其上的彙總層。專案不取代流程，而是將相關流程聚合，提供進度彙總、延遲／超前判斷與專案行事曆。

### 1.1 名詞定義

- **專案（Project）**：跨流程的管理單位，含名稱、客戶、負責人、預計起迄日。
- **流程（Flow / 案件）**：掛載於專案下的實際作業流程實例（即既有的銷售／導入／環境建置／客製化案件）。
- **預期進度（Expected Progress）**：依流程計畫起迄與當前日期推算「應完成」的比例。
- **實際進度（Actual Progress）**：流程目前實際完成比例。
- **排除日（Exclusion Date）**：專案行事曆中標記為不可排程的日期區間。

## 2. 角色與權限

| 角色 | 可檢視 | 可編輯 |
|------|--------|--------|
| 部門主管 | 所有專案 | 建立／編輯／刪除專案、串接流程、設定行事曆、簡報 |
| 顧問 | 自身負責或參與的專案 | 編輯所負責專案之流程掛載、行事曆排除日 |
| 工程主管 | 與工程相關之專案 | 檢視為主；可回報所轄流程進度 |
| 工程師 | 自身參與流程所屬專案 | 僅檢視 |
| 業務 | 自身來源案件所屬專案 | 僅檢視 |

權限原則：以角色控管可見專案範圍與可操作動作；專案層級的編輯（行事曆、流程掛載）以主管／該專案負責顧問為主。實際權限對應可由 Microsoft Entra ID 群組設定（見總體規格第 9 章）。

### 3.1 Project（專案）

| 欄位 | 型別 | 必填 | 說明 |
|------|------|------|------|
| id | string | 是 | 專案唯一識別碼 |
| name | string | 是 | 專案名稱 |
| client | string | 是 | 客戶名稱 |
| owner | string | 是 | 專案負責人（對應系統使用者） |
| planStart | date | 是 | 預計開始日 |
| planEnd | date | 是 | 預計結束日 |
| status | enum | 是 | 進行中 / 已完成 / 暫停 / 取消 |
| flows | Flow[] | 否 | 掛載之流程清單（見 3.2） |
| exclusions | Exclusion[] | 否 | 專案行事曆排除日（見 3.3） |
| createdBy / createdAt | string / datetime | 是 | 建立者與時間 |

### 3.2 ProjectFlow（專案下的流程掛載）

| 欄位 | 型別 | 必填 | 說明 |
|------|------|------|------|
| flowId | string | 是 | 對應實際案件（流程實例）ID |
| flowType | enum | 是 | 銷售 / 系統導入 / 環境建置 / 客製化 |
| name | string | 是 | 顯示名稱 |
| planStart | date | 是 | 此流程於專案中的計畫開始日 |
| planEnd | date | 是 | 此流程於專案中的計畫結束日 |
| progress | number(0-100) | 是 | 實際完成比例 |
| caseRef | string | 否 | 連結至案件詳情之引用（供點擊跳轉） |

備註：流程之間可有時間先後與重疊（例如導入尚未結束即開始環境建置）。

### 3.3 Exclusion（排除日）

| 欄位 | 型別 | 必填 | 說明 |
|------|------|------|------|
| from | date | 是 | 起始日 |
| to | date | 是 | 結束日（含當日） |
| reason | string | 是 | 原因（如客戶端系統凍結、盤點、客戶休假） |
| source | enum | 否 | 客戶提供 / 內部判斷 |

## 4. 進度計算規則

### 4.1 流程進度認定

`progress`（實際完成比例）之來源，待主管確認採下列何種（見第 9 節待釐清）：

- 步驟完成比例：已完成步驟數 ÷ 總步驟數。
- 加權工時：依各步驟預估工時加權。
- 人工填報：由承辦人員回報百分比。

預設建議：以「步驟完成比例」為主，因流程本身已以步驟管控。

### 4.2 預期進度（Expected Progress）

以線性時間推估：

```
expected = clamp( (today - planStart) / (planEnd - planStart), 0, 1 ) × 100%
```

- `today < planStart`：流程尚未開始，狀態為「未開始」。
- `today > planEnd`：expected = 100%。

進階（可選）：計算時可扣除排除日與國定假日，使預期進度以「工作日」為基準，更貼近實際（見 4.4）。

### 4.3 延遲 / 超前判斷

令 `delta = actual − expected`（百分點）：

| 條件 | 狀態 | 說明 |
|------|------|------|
| progress ≥ 100 | 完成 | 流程已完成 |
| today < planStart | 未開始 | 尚未進入計畫區間 |
| delta < −T | 延遲 | 落後預期，以 `delta` 呈現落後百分點 |
| delta > +T | 超前 | 領先預期 |
| −T ≤ delta ≤ +T | 準時 | 落在容許區間 |

`T` 為容許門檻，預設 ±8%（可由設定調整，見第 9 節）。狀態亦可換算為天數呈現（落後 ≈ delta% × 流程工期）。

### 4.4 與行事曆的關係

- 流程排程與時程計算應避開「排除日」與國定假日 / 連假（見總體規格第 8.3 節）。
- 排除日落在流程計畫區間內時，建議將該流程的 `planEnd` 順延對應工作日數，並於甘特圖標示。
- 本模組之排除日與系統層級之國定假日判斷併行套用，兩者皆會影響時程重算。

## 5. 畫面與互動

### 5.1 專案管理主畫面

- **專案選擇器**：切換不同專案。
- **專案摘要**：名稱、客戶、負責人、計畫期間。
- **KPI 區**：整體進度（各流程進度平均）、延遲流程數、超前流程數、排除日區間數。
- **甘特圖時間軸**：見 5.2。
- **各流程進度狀態**：列出每個流程的狀態膠囊（完成 / 延遲 / 超前 / 準時 / 未開始）與差異百分比。
- **專案行事曆**：排除日清單與新增 / 移除。
- **簡報模式**按鈕：見 5.4。

### 5.2 甘特圖時間軸

- 橫軸為時間（依專案計畫期間，標示月份刻度）。
- 每個流程一列，長條表示計畫區間，內含完成比例填色與百分比。
- **今日基準線**：以垂直線標示當前日期。
- **排除日**：以斜線 / 網底區塊標示於對應日期範圍。
- 流程列狀態以顏色與膠囊呈現延遲 / 超前 / 準時 / 未開始。

### 5.3 與案件雙向導覽

- 甘特圖中有對應案件的流程列，點擊流程名稱可跳轉至該流程的「案件詳情」畫面。
- 案件詳情畫面顯示「所屬專案」，點擊可反向跳回該專案的專案管理畫面。
- 無對應案件之流程（如尚未建立案件者）不提供跳轉。

### 5.4 簡報模式

- 提供簡報 / 全螢幕呈現模式：隱藏側欄等次要介面、放大時間軸與重點資訊，供內部會議呈現。
- 可一鍵進入與退出，不影響資料。

## 6. 主要使用情境（流程）

### 6.1 建立專案並串接流程

1. 主管 / 顧問建立專案，填入名稱、客戶、負責人、預計起迄。
2. 將既有案件（流程實例）掛載至專案，設定各流程於專案中的計畫起迄。
3. 系統依進度與時間計算各流程狀態並呈現於甘特圖。

### 6.2 進度追蹤與風險掌握

1. 各流程進度隨案件推進自動更新（依 4.1 認定方式）。
2. 系統計算延遲 / 超前並於 KPI、甘特圖、狀態清單呈現。
3. 主管據以掌握風險，於會議以簡報模式呈現。

### 6.3 設定專案行事曆排除日

1. 客戶反應某段期間需排除作業 / 會議（如系統凍結）。
2. 於專案行事曆新增排除日（起、迄、原因）。
3. 系統於甘特圖標示，並於時程計算避開該區間。

## 7. 與其他模組之關係

- **流程 / 案件模組**：專案掛載流程實例；流程進度為專案進度之來源；雙向導覽。
- **行事曆 / 提醒（總體第 8.3 節）**：排除日與國定假日併行套用於時程計算。
- **Microsoft 365 登入（總體第 9 章）**：角色與專案可見範圍可由 Entra ID 群組對應。
- **ISO 27001（總體第 11 章）**：專案進度與排除日紀錄納入文件化軌跡，進度與決策可追溯。

---

## 8. 驗收條件（Acceptance Criteria）

1. 可建立 / 編輯 / 刪除專案，並設定名稱、客戶、負責人、計畫起迄。
2. 可將流程掛載至專案，並於甘特圖正確呈現各流程計畫區間與完成比例。
3. 甘特圖顯示今日基準線；位置與當前日期一致。
4. 系統依 4.2／4.3 規則正確標示完成 / 延遲 / 超前 / 準時 / 未開始，且差異百分比正確。
5. 可新增 / 移除排除日，甘特圖即時以標示呈現，且時程計算避開該區間。
6. 甘特圖流程列可跳轉對應案件詳情；案件詳情可反向跳回所屬專案。
7. 簡報模式可正常進入 / 退出，呈現適合會議的版面。
8. 權限：不同角色僅能檢視 / 編輯其權限範圍內之專案。

## 9. 待釐清 / 待補充問題

1. **進度認定方式**：採步驟完成比例 / 加權工時 / 人工填報？是否混用？
2. **容許門檻 T**：延遲 / 超前的容許百分比（預設 ±8%）是否合適？是否依流程類型不同？
3. **預期進度基準**：以日曆日或工作日（扣除排除日 / 假日）計算？
4. **專案與流程關係**：一個專案是否可跨多個客戶？同一流程可否同時隸屬多個專案？
5. **排除日來源與套用**：排除日由客戶提供或內部判斷？是否區分「全專案」與「特定流程」之排除？
6. **時程順延規則**：排除日落在流程區間內時，順延 planEnd（順延工作日數）或維持原訂只標示？
7. **狀態換算天數**：延遲 / 超前是否需同時以「天數」呈現供溝通？
