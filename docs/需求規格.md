## 1. 文件目的與範圍

### 1.1 目的

本文件整理資訊部門內部工作流程之需求，作為後續建置「工作流程管理系統」之需求依據。系統目標為：將部門內部各項作業（銷售、導入、客製化、環境建置等）以可定義之流程進行標準化管控，明確規範每一步驟的負責人、應填寫之表單與應產出之文件，並保留可由部門自行定義流程內容的彈性。最終期望部門內所有人員的作業均能由系統進行管控與追蹤。

### 1.2 範圍

涵蓋資訊部門以下角色與流程：

- 角色：業務、顧問、工程師（含工程主管）、部門主管。
- 流程：銷售流程、系統導入流程、環境建置流程、客製化（需求變更）流程。
- 專案管理：以專案串接上述流程，掌握整體進度。
- 整合需求：Microsoft 365 帳號登入（SSO）、行事曆判斷（避開連假遞延）、專案行事曆、任務附件 / 連結、ISO 27001 文件化需求對應。

### 1.3 暫不納入範圍（本階段）

- 助理之作業（目前主要為操作手冊撰寫、新產品測試），本階段暫不評估，但系統設計應預留未來納入之擴充空間。

## 2. 組織與角色

| 角色 | 主要職責 | 在流程中的定位 |
|------|----------|----------------|
| 部門主管 | 部門整體管控、流程定義與審核 | 流程設計者、最終審核者，期望可綜覽所有人員作業 |
| 業務 | 業務開發、客戶拜訪、報價、簽約 | 銷售流程發起人 |
| 顧問 | 系統導入、教育訓練、啟動會議、複測 | 導入流程負責人、客製化需求發起人、複測者 |
| 工程主管 | 客製化任務分派、工程資源調度 | 客製化流程指派者 |
| 工程師 | 環境建置、客製化開發、測試文件撰寫 | 建置與開發執行者 |
| 助理（暫不納入） | 操作手冊、新產品測試 | 未來擴充 |

## 3. 流程總覽

四大流程及其銜接關係如下：

1. **銷售流程**（業務）→ 成案後移交顧問。
2. **系統導入流程**（顧問）→ 啟動會議完成後移交工程師。
3. **環境建置流程**（工程師）→ 完成環境建置。
4. **客製化（需求變更）流程**（顧問發起 → 工程主管指派 → 工程師開發 → 顧問複測 → 上線）。

流程銜接：銷售流程 →（成案）→ 系統導入流程 →（啟動會議完成）→ 環境建置流程 →（上線運行）。系統上線後，客戶提出需求即觸發客製化流程。銷售失敗則記錄失敗原因，供改善分析。上述流程可由「專案」串接管理（見第 10 節）。

## 4. 銷售流程（業務）

### 4.1 流程說明

業務進行業務開發，依客戶來源、產品類型與銷售模式推進，期間可能多次拜訪與系統 Demo，全程留存紀錄。成案後移交顧問；失敗則記錄原因供改善分析。

### 4.2 客戶來源（可多選分類）

- 行銷管道
- 客戶介紹客戶（轉介）
- 業務自行開發
- 舊系統客戶升級
- 內部轉介

### 4.3 產品項目

人事系統、員工入口網站、績效考核、教育訓練、職能、招募等系統。

### 4.4 銷售模式

- **買斷制**：一次性購買。環境建置於客戶端採購主機後安排。
- **訂閱制**：週期性訂閱。環境建置以開立租戶方式進行。

### 4.5 流程步驟、產出與負責人

| 步驟 | 說明 | 負責人 | 應產出 / 表單 |
|------|------|--------|----------------|
| 1. 建立商機 | 記錄客戶來源、產品、銷售模式 | 業務 | 商機建立表 |
| 2. 拜訪 / Demo | 可多次，逐次記錄 | 業務 | 拜訪紀錄、會議記錄（可後續調閱） |
| 3. 報價 | 成案前提供報價 | 業務 | 報價單 |
| 4. 需求確認 | 客製需求蒐集 | 業務 / 顧問 | 客製需求文件 |
| 5a. 成案 | 簽約，移交導入 | 業務 | 報價單（定版）、客製需求文件 |
| 5b. 失敗 | 記錄結案 | 業務 | 失敗原因記錄（供改善分析） |

### 4.6 重點需求

- 拜訪行程與會議記錄需可重複新增、永久留存並可調閱。
- 成案時，報價單與客製需求文件需自動帶往後續導入與客製化開發階段。
- 失敗原因需可結構化分類，以利後續統計與改善分析。

## 5. 系統導入流程（顧問）

### 5.1 流程說明

成案後由業務移交顧問。顧問負責安排系統導入與教育訓練，並與客戶召開啟動會議。啟動會議完成後，將相關資訊移交工程師進行環境建置。

導入流程可由部門**預先定義**：預計的工作流程、每個時間點應完成的工作內容、各時間點需填寫的表單與應提供的文件。系統應於各計畫時間點主動提醒作業人員應完成事項。

### 5.2 流程步驟、產出與負責人

| 步驟 | 說明 | 負責人 | 應產出 / 表單 |
|------|------|--------|----------------|
| 1. 接收移交 | 接收銷售階段文件 | 顧問 | 報價單、客製需求文件（自前段帶入） |
| 2. 導入規劃 | 安排導入時程與教育訓練 | 顧問 | 導入計畫表 |
| 3. 啟動會議 | 與客戶確認啟動 | 顧問 | 啟動會議記錄 |
| 4. 蒐集客戶資料 | 依預定義表單蒐集 | 顧問 / 客戶 | 人員資料表、委任權限表（簽核） |
| 5. 移交工程 | 啟動會議後移交 | 顧問 | 移交清單 |

### 5.3 重點需求

- 流程、時間點、表單、應產出文件均可由部門**自行定義**。
- 各計畫時間點應提供對應文件並主動提醒負責人。
- 表單種類示例：客戶人員資料表、委任權限表（需簽核）。
- 需整合行事曆判斷：遇連假應自動評估時程遞延（見第 8 節）。

## 6. 環境建置流程（工程師）

### 6.1 流程說明

顧問完成啟動會議後移交工程師。工程師依銷售模式建置環境：

- **買斷制**：待客戶端採購主機後，安排主機環境建置。
- **訂閱制**：開立租戶。

### 6.2 流程步驟、產出與負責人

| 步驟 | 說明 | 負責人 | 應產出 / 表單 |
|------|------|--------|----------------|
| 1. 接收移交 | 接收導入移交清單 | 工程師 | 移交清單 |
| 2a. 主機建置（買斷） | 客戶採購主機後建置 | 工程師 | 環境建置檢核表 |
| 2b. 租戶開立（訂閱） | 開立租戶 | 工程師 | 租戶開立紀錄 |
| 3. 環境驗收 | 確認環境就緒 | 工程師 / 顧問 | 環境驗收表 |

### 6.3 重點需求

- 依銷售模式（買斷 / 訂閱）走不同建置分支。
- 買斷制需等待客戶採購主機之前置條件，系統應可記錄此等待狀態。

## 7. 客製化（需求變更）流程

### 7.1 流程說明

客戶於系統上線後提出客製需求，由顧問發起需求變更流程，指派工程主管；工程主管再指派工程師開發。開發完成後須撰寫測試文件，交付顧問複測；複測通過後更新至客戶測試區，驗證無誤後再更新至客戶正式區。

### 7.2 流程步驟、產出與負責人

| 步驟 | 說明 | 負責人 | 應產出 / 表單 |
|------|------|--------|----------------|
| 1. 發起需求變更 | 接收客戶需求並登錄 | 顧問 | 需求變更單 |
| 2. 指派 | 指派工程主管 | 顧問 | （流程指派） |
| 3. 分派開發 | 指派工程師 | 工程主管 | 開發任務單 |
| 4. 客製開發 | 完成開發 | 工程師 | 開發紀錄 |
| 5. 撰寫測試文件 | 開發後撰寫 | 工程師 | 測試文件 |
| 6. 複測 | 顧問複測驗證 | 顧問 | 複測報告 |
| 7. 更新測試區 | 複測通過後 | 工程師 | 測試區更新紀錄 |
| 8. 更新正式區 | 測試區無誤後 | 工程師 | 正式區上線紀錄 |

### 7.3 重點需求

- 複測不通過需可退回工程師重新開發（流程可循環）。
- 測試區 → 正式區為兩道關卡，須分別記錄與確認。

## 8. 共通功能需求

### 8.1 流程定義（彈性）

- 部門主管可自行定義流程：步驟、順序、負責角色、各步驟應填表單與應產出文件。
- 可決定每一步驟完成後的下一步驟與負責人。
- **每個步驟可附加作業範本檔**（如表單範本、檢核表、SOP 文件），供承辦人員下載填寫，使作業有一致依據。
- 在標準化的同時保留調整彈性。

### 8.2 表單與產出文件管理

- 表單與文件內容可由部門自行定義（含簽核類表單，如委任權限表）。
- 各流程時間點自動帶出對應表單並提醒負責人填寫 / 完成。
- 前段產出（如報價單、客製需求文件）可自動帶往後續流程引用。

### 8.3 提醒與時程

- 於各計畫時間點主動提醒作業人員應完成事項。
- **行事曆整合**：自動判斷國定假日 / 連假，避免任務排程落在假期；必要時自動遞延並重算時程。
- 另支援專案層級之行事曆排除日（見第 10.5 節）。

### 8.4 紀錄與調閱

- 拜訪紀錄、會議記錄、各式產出文件須永久留存並可隨時調閱。
- 失敗 / 退回等狀態須留存原因，供後續分析改善。

### 8.5 權限與綜覽

- 依角色控管可見與可操作之流程與表單。
- 部門主管可綜覽所有人員作業進度。

### 8.6 附件與連結管理

- 每一項任務 / 步驟 / 表單均可加掛附件，作為任務內容的佐證或交付物。
- 支援兩種附加方式：
  - **上傳檔案附件**：直接上傳檔案（如報價單 PDF、會議簡報、測試截圖等），存於系統並與任務綁定。
  - **連結方式**：以超連結引用外部資源（如 SharePoint / OneDrive 文件、Teams 會議錄影、外部網址），不複製檔案本體。
- 由於公司主要使用 Microsoft 365，連結方式應優先支援 SharePoint / OneDrive 文件連結，使附件可沿用既有雲端權限與版本控管。
- 附件需記錄上傳者、時間與版本，並隨任務 / 案件永久留存、可隨時調閱。
- 附件需納入 ISO 文件化軌跡（見第 11 節），作為流程紀錄之佐證。
- 建議限制：可設定允許的檔案類型與單檔大小上限（待第 12 節確認）。

## 9. 帳號與登入整合（Microsoft 365）

### 9.1 需求說明

公司主要使用 Microsoft Office 365，使用者登入驗證希望整合 Microsoft 帳號（Microsoft Entra ID，前稱 Azure AD），讓員工以既有的公司 Microsoft 帳號單一登入（SSO），免再維護一組系統帳密。

### 9.2 功能需求

- **單一登入（SSO）**：以 Microsoft Entra ID 進行身分驗證（建議採 OAuth 2.0 / OpenID Connect）。
- **帳號對應**：登入後的 Microsoft 帳號自動對應至系統使用者與其角色（業務 / 顧問 / 工程主管 / 工程師 / 主管）。
- **角色與權限**：可由 Entra ID 群組對應系統角色，或於系統內另行指派；角色決定可見流程與可操作步驟。
- **離職 / 停用連動**：帳號於 Entra ID 停用後，系統登入即失效（依公司帳號生命週期管理）。
- 可保留少量本機 / 例外帳號機制（如外部顧問），作為非必要之備援。

### 9.3 與附件 / 連結整合

- 登入既有 Microsoft 身分後，附件之 SharePoint / OneDrive 連結可沿用使用者既有雲端存取權限，降低重複授權。

### 9.4 安全與 ISO 對應

- SSO 與權限控管對應 ISO 27001 A.5 存取控制；登入紀錄可作為稽核軌跡（見第 11 節）。

## 10. 專案管理

### 10.1 目的

提供「專案」作為串接各流程的管理單位。一個專案（通常對應一個客戶案）可包含多個流程（銷售、導入、環境建置、客製化等），透過專案即可掌握該案整體進度、各流程銜接狀態，並支援會議簡報與時程管理。

### 10.2 建立專案與串接流程

- 可建立專案項目，設定名稱、客戶、負責人、預計起迄日。
- 將相關流程（案件）掛載至專案之下，形成專案的流程清單。
- 流程之間可有時間先後與重疊（如導入尚未結束即開始環境建置）。
- 由專案即可向下查看各流程目前所在步驟與負責人。

### 10.3 進度呈現

- 以**甘特圖時間軸**呈現專案下各流程的計畫區間與完成比例。
- 顯示「今日」基準線，標示各流程目前進度。
- 提供整體進度（各流程進度彙總）與單一流程進度。

### 10.4 進度判斷：延遲 / 超前

- 系統依各流程計畫起迄與目前日期計算「預期進度」，與「實際完成比例」比較。
- 實際低於預期 → 標示**延遲**；高於預期 → 標示**超前**；落在容許區間 → **準時**。
- 延遲 / 超前以差異百分比（或天數）呈現，供主管掌握風險。
- 容許門檻（如 ±8%）可後續設定（待第 12 節確認）。

### 10.5 專案行事曆（排除日）

- 可為專案定義專屬行事曆，設定**排除日**：客戶反應需排除的作業或會議日期（如客戶端系統凍結、盤點期間、客戶休假）。
- 排程與時程計算應避開排除日；甘特圖以標示（如斜線 / 網底）呈現排除區間。
- 排除日與第 8.3 節之國定假日 / 連假判斷併行套用。

### 10.6 簡報用途

- 專案進度畫面需可作為內部會議簡報之用：提供簡報 / 全螢幕呈現模式（隱藏次要介面、放大時間軸與重點資訊）。
- 以視覺化方式呈現各流程進度、延遲 / 超前狀態，利於會議溝通。

### 10.7 重點需求

- 專案為跨流程的彙總視角，需即時反映其下各流程的最新進度。
- 進度、延遲 / 超前、排除日皆需可追溯。

## 11. ISO 27001 文件化需求對應框架

> 內部已導入 ISO 27001。期望系統內的流程表單能取代現行 ISO 文件，將 ISO 的文件化需求整合進系統流程中。以下為對應框架（待後續逐項細化）。

### 11.1 對應原則

- 每一張系統表單 / 產出文件，對應一份 ISO 文件化紀錄（document / record）。
- 系統需提供：文件版本控管、簽核軌跡、留存期限、可追溯性（誰、何時、做了什麼）。
- 以系統流程的「強制填寫 / 簽核」取代人工維護 ISO 文件之需求。

### 11.2 對應對照表（初版，待補充）

| 系統表單 / 產出 | 對應 ISO 27001 需求面向 | 備註 |
|------------------|--------------------------|------|
| 委任權限表（簽核） | 存取控制、權限授予紀錄 | 需簽核軌跡 |
| 人員資料表 | 個資 / 資產盤點相關 | 留存與保護 |
| 會議記錄 / 啟動會議記錄 | 溝通與決策紀錄 | 可追溯 |
| 測試文件 / 複測報告 | 變更管理、測試紀錄 | 對應變更控制 |
| 需求變更單 | 變更管理流程 | 變更申請與核准 |
| 環境建置 / 驗收檢核表 | 營運安全、組態管理 | 建置與驗收佐證 |
| 失敗原因 / 退回紀錄 | 改善 / 矯正措施 | 持續改善佐證 |
| 作業範本檔（流程步驟） | 文件化資訊管制 | 範本版本控管 |
| Microsoft 365 登入紀錄 | A.5 存取控制 / 稽核軌跡 | SSO 登入與權限變更紀錄 |

### 11.3 待確認事項

- 現行 ISO 文件清單與其對應之管制措施（Annex A 控制項）尚需主管提供，以完成完整對應。
